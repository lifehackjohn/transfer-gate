1. Layout Philosophy

Transfer Gate v2 uses a purpose-built layout designed around the core workflow of triaging unsorted files into a structured Cabinet. Every design decision serves one goal: reduce friction between seeing a file and deciding where it goes.

  • Two-panel core. The left panel shows source content (unsorted files or batch files); the right panel shows the destination Cabinet tree. This follows a "sort left, file right" mental model — the eye scans left-to-right, matching the decision flow from "what is this?" to "where does it belong?"
  • Bottom action bar. Primary action buttons and summary statistics live in a persistent bar anchored to the bottom of the viewport. The user never needs to scroll to act.
  • Top status bar (header). Displays the current mode (Online/Offline), Cabinet path, connection status, and configuration access. Provides constant orientation.
  • No scrolling to act. All primary actions (Accept, Skip, Stage Batch, Place Files) are always visible without scrolling. Only the file list and tree scroll.
  • Single HTML file. The entire UI ships as one self-contained HTML file that adapts its panels and controls depending on whether the app is running online or offline.
  • "Sort left, file right" mental model. The left panel is always the working area (files to process), the right panel is always the reference area (where things go). This stays consistent across both modes.
Design principle: The interface should feel like sorting physical papers on a desk — the unsorted pile on the left, the filing cabinet on the right, and a workspace in between. Every interaction moves something from left to right.

2. Shared Shell

The shell wraps both online and offline modes with consistent chrome. It provides persistent orientation (mode, status, Cabinet path) and access to configuration, while the inner panels swap depending on the active mode.

Header Bar

The header bar stretches across the full viewport width and contains, from left to right:

ElementDescription
Status dotGreen = online (server reachable), Amber = offline (no server), Grey = detecting connection
App titleFixed text: "Transfer Gate"
Mode labelDynamic text, e.g., "Online — Sort & Stage" or "Offline — Verify & Place"
Cabinet pathDisplays the configured Cabinet root with validation indicator (green checkmark if valid, red X if invalid/missing)
SpacerFlexible space pushing remaining elements to the right
Config buttonGear icon; opens the Settings overlay
Mode dropdownManual override to switch between Online and Offline modes

Action Bar

The action bar is anchored to the bottom of the viewport. It contains:

  • Left side — summary stats: Running counts of file states, e.g., 12 pending | 5 accepted | 2 skipped | 1 conflict
  • Right side — action buttons:
    • Primary: "Stage Batch" (online mode) or "Place Files" (offline mode)
    • Secondary: "Skip All Remaining", "Export Structure"

3. Online Mode — Sort & Stage

Online mode is the primary workflow. The server is reachable, AI suggestions are available, and the user triages files one by one (or in bulk) before staging a batch for later offline placement.

Left Panel: Unsorted Files

  • Panel header: "Unsorted Files" with a count badge (e.g., 24 files)
  • Search/filter bar: Sits below the panel header. Allows filtering by filename, extension, or suggestion status.
  • Scrollable file card list: Each file is a self-contained card with all decision controls inline.

File Card Anatomy

Each file card is a self-contained decision unit containing the following elements, top to bottom:

  1. Original filename — Bold, truncated with ellipsis if longer than the card width.
  2. File metadata row — Extension badge (color-coded by file type), file size, last modified date.
  3. AI suggestion badge — Shows the suggested destination folder path with a confidence indicator (e.g., "10 Finance/Tax — 87%").
    • Blue badge if confidence > 70% (high)
    • Amber badge if confidence 40–70% (medium)
    • Grey badge if confidence < 40% or unavailable (low)
  4. Destination dropdown — Pre-filled with the AI suggestion. Opens the full Cabinet tree for manual override.
  5. Rename field — Text input pre-filled with the suggested name. If the name is unchanged from the original, the field shows a highlighted (amber) border as a mandatory rename indicator.
  6. Decision buttons row — Accept (green), Skip (grey), Override (blue, shown when the user changes the destination from the AI suggestion).

File Card States

StateVisual Indicator
PendingDefault card styling, no border highlight
AcceptedGreen left border, green checkmark icon, muted (non-interactive) controls
OverriddenBlue left border, blue checkmark icon, original AI suggestion shown struck through
SkippedGrey left border, grey styling, card collapses to single line
ConflictRed left border, red warning icon, conflict detail message shown

Right Panel: Cabinet Tree

  • Panel header: "Cabinet" with folder count badge
  • Tree view: Hierarchical folder listing with expand/collapse toggles
  • Each folder shows: name, file count badge, accepted file types (from structure rules)
  • Folders with pending file assignments are highlighted with a blue background
  • Drop target highlighting when dragging files (future enhancement)

4. Offline Mode — Verify & Place

Offline mode is the execution phase. The USB/disk has been transported to the Cabinet machine. The app loads the placement manifest, verifies file integrity, and places files into the Cabinet tree.

Left Panel: Batch Files

  • Panel header: "Batch: batch-20261107-143022" with file count
  • Batch selector: Dropdown for choosing between multiple batches if the inbox contains more than one
  • File list: Each file card shows its verification status and placement details

Verification status icons:

IconMeaning
✓ Green checkmarkVerified — SHA-256 checksum matches the manifest
✗ Red XFailed — checksum mismatch, file may be corrupt or tampered
● Grey spinnerVerification in progress
— Grey dashNot yet checked (queued)

Each file card in offline mode displays:

  1. Renamed filename — The new name from the placement manifest (bold)
  2. Original filename — Shown smaller and muted beneath the renamed name
  3. Destination path — Full Cabinet path where the file will be placed
  4. Verification status — Icon and SHA-256 match/mismatch detail
  5. File size — Displayed for quick reference

Right Panel: Placement Preview

  • Panel header: "Placement Preview"
  • Shows the Cabinet tree with destination folders highlighted
  • Each highlighted folder shows the count of files about to be placed into it
  • Conflict indicators appear on folders where naming or path conflicts exist
  • Expanding a folder reveals individual file placement entries

5. Settings Overlay

The settings overlay is a modal dialog that appears centered over the main content with a semi-transparent backdrop. It provides access to all configuration options without leaving the current workflow context.

Settings Fields

#FieldTypeDescription
1 Cabinet Root Path Text input + Browse button Filesystem path to the Cabinet root. Shows validation status: green check = valid path, red X = invalid or missing.
2 oMLX Endpoint Text input URL of the local oMLX server (default: http://localhost:8000/v1). Shows connection status indicator.
3 Server Port Number input Port for the Transfer Gate server (default: 8080).
4 Media File Naming Rule Text input + preview Template syntax for renaming media files, e.g., {date} {title}. A live preview shows the applied result.
5 Structure Rules Editor Textarea (monospace) Embedded YAML editor for structure-rules.yaml content. Monospace font, no syntax highlighting required.
6 Exclude Patterns Editable list Filename patterns to auto-skip (e.g., .DS_Store, @eaDir, Thumbs.db).

The overlay footer contains Save and Cancel buttons.
