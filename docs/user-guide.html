1. Overview

Transfer Gate is a portable file sorting application designed for moving files from an unsorted staging area into a structured archive (the "Cabinet"). It bridges two environments:

  • Online Zone (NAS/Linux): Where unsorted files accumulate and AI-assisted classification happens. Requires Python 3 and a browser.
  • Offline Zone (Air-gapped Windows): Where the Cabinet archive lives. Files are verified and placed into their permanent locations. Requires PowerShell 5.1+ and a browser.

The workflow is: classify and stage files online, transfer via USB, verify and place files offline. A manifest system ensures no data is lost and provides checksums for integrity verification.

Key Concepts

  • Cabinet: Your root archive folder (e.g., D:\Archive). Contains a hierarchical folder structure that serves as your filing taxonomy.
  • Batch: A timestamped folder containing files staged for transfer, along with manifest files.
  • Manifest: JSON files that track what files are in a batch, where they should go, and whether they arrived intact.
  • oMLX: A local AI model that suggests where files should be filed. Optional — the app works without it.

2. Installation

Transfer Gate requires no installation. The entire application is a set of files you copy to wherever you need them.

Files You Need

File Required Zone Purpose
transfer-gate.html Yes Both The UI — open in any browser
transfer-gate-server.py Yes (online) Online Python backend server
transfer-gate.ps1 Yes (offline) Offline PowerShell engine
transfer-gate.json Yes Both Configuration file
structure-rules.yaml Optional Both Folder metadata and rules
start-transfer-gate.command Optional Online (Mac) Double-click launcher for macOS — starts server and opens browser
Start-TransferGate.bat Optional Offline (Win) Double-click launcher for Windows offline (PowerShell) — no Python
Start-TransferGate-Online.bat Optional Online (Win) Online server launcher — system Python, or python-portable\, or one-time embed download
python-portable\ Optional (Win) Online (Win) Embeddable CPython runtime (not in git; created by Online launcher if needed)

System Requirements

Online Zone:

  • Python 3.8 or later (standard library only; pyyaml optional for structure rules)
  • Chrome 90+ or Edge 90+ browser
  • Network access to localhost only (no internet required)
  • oMLX local LLM endpoint (optional, for AI classification)

Offline Zone:

  • Windows PowerShell 5.1+ (ships with Windows 10/11)
  • Chrome 90+ or Edge 90+ browser
  • No Python required
  • No network access required

Setup Steps

  1. Copy the TransferTool/ folder to your online machine (e.g., the NAS).
  2. Copy the same TransferTool/ folder to your offline machine (e.g., the Cabinet workstation).
  3. Edit transfer-gate.json on each machine to set the correct cabinetRoot path.
  4. (Online only) If you have oMLX set up, ensure the endpoint URL is correct in config.

Quick Start with Launchers

Platform launchers let you start Transfer Gate with a double-click — no terminal needed.

macOS (Online Zone):

  1. Double-click start-transfer-gate.command in Finder.
  2. A Terminal window opens, starts the Python server, and opens http://127.0.0.1:8080 in your default browser.
  3. Close the Terminal window (or press Ctrl+C) to stop the server.

Windows (Online Zone — Python server):

  1. Double-click Start-TransferGate-Online.bat.
  2. Uses system Python 3.8+ if present; otherwise python-portable\python.exe; otherwise downloads embeddable Python 3.12.7 once (~15 MB).
  3. Starts transfer-gate-server.py and opens http://127.0.0.1:8080.

Windows (Offline Zone — PowerShell):

  1. Double-click Start-TransferGate.bat.
  2. A Command Prompt window opens, starts the PowerShell server, and opens http://127.0.0.1:8080 in your default browser.
  3. Close the Command Prompt window to stop the server.
Tip The launchers use the default port 8080. To change the port for the Mac launcher, set the TG_PORT environment variable before running (e.g., TG_PORT=9090). For Windows, edit the port in transfer-gate.json.

3. Configuration

Transfer Gate uses a single JSON configuration file: transfer-gate.json, located in the same folder as the scripts.

Configuration Format

{
    "cabinetRoot": "D:\\Archive",
    "inbox": "00 Inbox",
    "manifestOutput": "gate-out",
    "exclude": [
        ".DS_Store",
        "@eaDir",
        ".Trashes",
        ".TemporaryItems",
        "#recycle",
        ".streams",
        "$RECYCLE.BIN",
        "System Volume Information"
    ],
    "mediaFileNamingRule": "{date} {title}",
    "omlxEndpoint": "http://localhost:8000/v1",
    "serverPort": 8080
}

Configuration Keys

Key Type Default Description
cabinetRoot string (required) Absolute path to the Cabinet root folder
inbox string "00 Inbox" Relative path (from cabinetRoot) to the inbox folder for incoming batches
manifestOutput string "gate-out" Relative path (from working directory) for staged batch output
exclude string[] (system files) Filenames to ignore when scanning directories
mediaFileNamingRule string "{date} {title}" Template for suggested filenames
omlxEndpoint string "http://localhost:8000/v1" URL of the local oMLX LLM endpoint
serverPort number 8080 Port for the local HTTP server

cabinetRoot Explained

This is the most important setting. It tells Transfer Gate where your archive lives. Examples:

  • Windows: "D:\\Archive" or "E:\\Cabinet"
  • UNC: "\\\\NAS\\share\\Archive" (note double backslash escaping in JSON)
  • Linux/macOS: "/volume1/Archive" or "/mnt/archive"

When you move your Cabinet to a different drive, just update this one value. No other changes needed.

v1 Migration If you have an older config with archiveRoot instead of cabinetRoot, Transfer Gate will automatically migrate it on first run. Your old config is preserved.

4. Online Usage (Sort & Stage)

Starting the Server

Easy way (macOS): Double-click start-transfer-gate.command — it starts the server and opens the browser automatically.

Manual way: Open a terminal on your online machine and run:

cd /path/to/TransferTool
python3 transfer-gate-server.py

Optional flags:

python3 transfer-gate-server.py --port 9090          # Custom port
python3 transfer-gate-server.py --root /path/to/tosort  # Custom source directory
python3 transfer-gate-server.py --cabinet /volume1/Archive  # Override cabinet path

The server will print a message like:

Transfer Gate v2 server running on http://127.0.0.1:8080
Cabinet: /volume1/Archive
Source:  /volume1/tosort

Opening the Browser

Navigate to http://localhost:8080 in Chrome or Edge. The UI will load and auto-detect online mode (green status dot in header).

Loading Files

The left panel ("Unsorted Files") automatically shows all files found in your tosort/ directory. Each file card displays:

  • Original filename
  • File extension badge
  • File size
  • Last modified date

AI Classification

If oMLX is available, each file card will show an AI suggestion badge indicating:

  • Suggested destination folder (e.g., "10 Finance/Tax")
  • Confidence score (e.g., 87%)

The suggestion is based on the file's name, extension, and metadata matched against your Cabinet's folder structure. Files are NOT sent to the AI — only metadata.

Tip Better structure rules = better AI suggestions. Add descriptions to your folders in structure-rules.yaml to help the AI understand what belongs where.

Reviewing Suggestions

For each file, you can:

  1. Accept — Click the green Accept button to approve the AI suggestion (or your manual selection).
  2. Override — Change the destination folder using the dropdown, then click Accept.
  3. Skip — Click Skip to exclude the file from this batch.

Mandatory Rename

Every file MUST be renamed before it can be staged. The rename field is pre-filled with a suggested name based on your naming rule (e.g., "{date} {title}"). The field is highlighted if the name has not been changed from the original filename.

Warning You cannot stage a file with its original filename. This is intentional — it enforces consistent naming in your archive. Change the name to match your naming convention (e.g., "2026-11-07 Invoice from Vendor.pdf").

Staging a Batch

Once you have accepted all desired files:

  1. Review the summary in the action bar (e.g., "8 accepted, 2 skipped").
  2. Click "Stage Batch".
  3. The server creates a timestamped batch folder in gate-out/ containing:
    • payload/ — the renamed files
    • placement-manifest.json — maps each file to its destination
    • transfer-manifest.json — SHA-256 checksums for verification
  4. Copy the batch folder to a USB stick for transfer to the offline machine.

5. USB Transfer

From Online to Offline

  1. Locate the batch folder in your gate-out/ directory (e.g., gate-out/batch-20261107-143022/).
  2. Copy the entire batch folder to a USB stick.
  3. Carry the USB to your offline (air-gapped) machine.
  4. Copy the batch folder into the Cabinet's inbox folder (e.g., D:\Archive\00 Inbox\).

From Offline to Online (Return Trip)

  1. After placing files, copy the placement-receipt.json from the batch folder back to USB.
  2. Optionally run transfer-gate.ps1 -Mode export to generate an updated offline-structure-manifest.json and copy that to USB as well.
  3. Return USB to online machine.
  4. The placement receipt tells the online side that files were successfully placed and source copies can be safely deleted.
The Two-Phase Prune Contract Source files in tosort/ are NEVER deleted until a verified placement receipt returns through the gate. This ensures zero data loss even if the USB stick is lost or corrupted.

6. Offline Usage (Verify & Place)

Option A: Double-Click Launcher (Easiest)

Double-click Start-TransferGate.bat. It starts the PowerShell server and opens the browser automatically. No terminal commands needed.

Option B: Using the PowerShell Server (Manual)

cd D:\path\to\TransferTool
powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1 -Mode serve

Then open http://localhost:8080 in a browser. The UI auto-detects offline mode (amber status dot).

Option C: Opening HTML Directly

Double-click transfer-gate.html to open it in your browser. Without a server, it runs in limited offline mode using localStorage.

Option D: Command-Line Only

# Verify all batches in inbox
powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1 -Mode verify

# Place files from a specific batch
powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1 -Mode place -BatchPath "D:\Archive\00 Inbox\batch-20261107-143022"

# Export Cabinet structure
powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1 -Mode export

# Run verify + export (default)
powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1

Selecting a Batch

In the UI, the left panel shows available batches in the inbox folder. Select a batch to see its contents.

Verification

Each file in the batch is checked against its transfer-manifest.json:

  • File exists in payload/
  • File size matches
  • SHA-256 checksum matches

Status indicators:

  • Green checkmark = verified
  • Red X = failed (checksum mismatch or missing file)
  • Grey spinner = in progress
Warning If any file fails verification, do NOT place that file. The USB transfer may have corrupted it. Re-copy from the online machine.

Placement Preview

The right panel shows the Cabinet tree with highlighted destination folders. Expand a folder to see which files will be placed there.

Placing Files

  1. Review the placement preview.
  2. Click "Place Files".
  3. Each verified file is moved from the batch payload to its Cabinet destination.
  4. A placement-receipt.json is generated in the batch folder.

Conflict Handling

If a file with the same name already exists at the destination:

  • Skip: Leave the file in the batch (not placed).
  • Rename: Add a numeric suffix (e.g., "Document (2).pdf").
  • Overwrite: Replace the existing file (use with caution).

7. Structure Rules

Structure rules are defined in structure-rules.yaml and provide metadata about your Cabinet's folder structure.

What They Do

  • Add human-readable descriptions to folders (used by AI for better classification)
  • Define accepted file types per folder (e.g., Finance only accepts pdf, xlsx, csv, docx)
  • Set naming conventions per folder
  • Define the folder hierarchy

Example structure-rules.yaml

folders:
  "00 Inbox":
    description: "Incoming unsorted files - staging area"
    accepts: ["*"]
  "10 Finance":
    description: "All financial documents"
    accepts: ["pdf", "xlsx", "csv", "docx"]
    naming: "YYYY-MM-DD Title (version)"
    children:
      "Banking":
        description: "Bank statements, correspondence"
      "Insurance":
        description: "Insurance policies, claims"
      "Tax":
        description: "Tax returns, assessments"
        children:
          "*":
            description: "Year subfolder, auto-created"
      "Invoices":
        description: "Invoices, receipts, billing"
  "20 Legal":
    description: "Legal documents"
    accepts: ["pdf", "docx"]
    children:
      "Contracts":
        description: "Signed contracts, agreements"
      "Filings":
        description: "Court filings, registrations"

Editing via UI

  1. Click the gear icon in the header to open Settings.
  2. Scroll to "Structure Rules Editor".
  3. Edit the YAML content.
  4. Click Save.

Changes take effect immediately for AI classification.

Tip Good descriptions help the AI. Instead of just "Tax", write "Tax returns, assessments, and correspondence with tax authorities". The more context, the better the classification.

8. Troubleshooting

oMLX Not Available

Problem: AI suggestion badges show "unavailable" or do not appear.

Cause: The oMLX endpoint is not running or the URL is incorrect.

Solution: Check that your local LLM is running and the endpoint URL in config matches. The app works fine without AI — just classify files manually.

Cabinet Path Invalid

Problem: Header shows "Cabinet: invalid" with red indicator.

Cause: The cabinetRoot path in config does not exist or is not accessible.

Solution: Open Settings and update the Cabinet Root Path to a valid, accessible directory. On Windows, ensure the drive is mounted. On NAS, ensure the volume is available.

File Conflicts During Placement

Problem: Files show conflict status during offline placement.

Cause: A file with the same name already exists at the destination.

Solution: Choose Skip (to leave it), Rename (to add a suffix), or Overwrite (to replace). Consider reviewing your naming conventions to avoid future conflicts.

PowerShell Execution Policy

Problem: Running transfer-gate.ps1 shows "execution of scripts is disabled".

Cause: Windows default execution policy blocks unsigned scripts.

Solution: Run with the bypass flag:

powershell -ExecutionPolicy Bypass -File .\transfer-gate.ps1

Or create a .bat launcher file containing that command.

Checksum Verification Fails

Problem: Files show red X during offline verification.

Cause: File was corrupted during USB transfer.

Solution: Re-copy the batch from the online machine. Do not place corrupted files. If the issue persists, try a different USB stick.

Large Files Are Slow

Problem: Staging or verification takes a very long time for large files.

Cause: SHA-256 checksum computation is CPU-intensive for multi-GB files.

Solution: This is expected behavior. The progress indicator shows computation status. A 2 GB file may take 30–60 seconds depending on hardware.

Settings Not Persisting

Problem: Settings revert after closing the browser.

Cause: In pure offline mode (no server), settings are stored in localStorage which is browser-specific.

Solution: Use the PowerShell serve mode (-Mode serve) instead of opening the HTML directly. Or edit transfer-gate.json manually.

System Summary

Transfer Gate is a three-component system:

  1. transfer-gate.html — Portable UI that works in both zones.
  2. transfer-gate-server.py — Python backend for the online zone.
  3. transfer-gate.ps1 — PowerShell engine for the offline zone.

These communicate via localhost HTTP. The HTML file detects its environment and adapts automatically. Data flows through USB batches with manifest files ensuring integrity at every step.
